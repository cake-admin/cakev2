# Agent instructions — cake& design system

## Implementing a component from Figma

To implement, port, or audit a component from a Figma link — or to plan a
devkit migration — read and follow
**[.claude/skills/figma-component-implementation/SKILL.md](.claude/skills/figma-component-implementation/SKILL.md)**.
It defines the full workflow: per-component Figma audit (MCP), token
extraction + verification, CSS custom-property styling rules, Radix mappings,
naming translation, tests policy, verification, and optional Code Connect.

## Component + Storybook documentation work

Before creating, modifying, or reviewing anything under
`src/cakeand/components/` (components or stories), read and follow
**[.claude/skills/storybook-component-docs/SKILL.md](.claude/skills/storybook-component-docs/SKILL.md)**.
It defines the mandatory docs-page template (section order, story taxonomy,
props-table rules, hard constraints, verification steps). Canonical exemplar:
`src/cakeand/components/Button/`.

## The designer starter (`starter/`)

`starter/` is the template designers scaffold from
(`npx degit cake-admin/cakev2/starter`). It is a standalone Vite app that
installs the published package from a **GitHub Release tarball URL**, which needs
no token — unlike GitHub Packages, which requires authentication for every
install even of public packages.

Two rules:

- **`starter/context/` is generated. Never hand-edit it.** Regenerate with
  `npm run build:agent-context -- --md-out starter/context --stamp <version>`,
  or let `scripts/bump-starter.mjs` do it as part of a release.
- **`starter/` is not an npm workspace, deliberately.** Making it one would hoist
  its dependencies into the root `node_modules` and change module resolution for
  both the CRA site and Storybook.

## Generated agent context

`scripts/build-agent-context.mjs` is the single generator for everything derived
from component docs. It parses the prose in each `*.stories.tsx`
(`parameters.docs.description.component`) once and emits:

- `--json-out` → `*.cake.json` for `cake-admin/ai-lab`. **Never overwrites an
  existing file** — hand-curated entries must survive a resync.
- `--md-out` → the two-tier markdown agents read. **Always fully regenerated.**

`scripts/build-knowledge.mjs` is a thin forwarder to the JSON half, kept because
it is the documented workflow. `scripts/lib/component-docs.mjs` holds the shared
parser; its helpers encode two bugs that were expensive to find (JavaScript has
no `\Z` regex anchor; CRLF checkouts break `$`-anchored patterns). Read the
comments before changing them.

Adding a component **folder** fails the generator until it is added to
`CATEGORIES` — a component missing from the index is one agents will never use.

## Where the generated context lives

`starter/context/` is the only copy that ships today. It is regenerated by the
**publish** workflow (via `scripts/bump-starter.mjs`) and stamped with the
released version — never on a main push. The starter pins an exact package
version, and its context must describe that exact version, or a designer's agent
is told about components their build does not contain.

The generator also supports `--llms`, which emits `llms.txt` / `llms-full.txt`
for serving over HTTP. Nothing invokes that today: `deploy.yml` does not generate
or publish context, so there is no `cake.lenovo.com/context/` or `/llms.txt`.
Do not link to those URLs until that step exists.

## Repo quirks

- The repo path contains `&`, which breaks npm `.bin` shims and `npx` on
  Windows. Invoke tool binaries via `node node_modules/<pkg>/<bin>.js` or the
  package scripts (which already do this). Storybook: `npm run storybook`
  (dev, port 6006) / `npm run build-storybook`.
- The `chart-tool-echarts/` folder is a separate Vite app (the data-viz tool
  deployed at cake.lenovo.com/datavis) with its own docs and scripts — its
  token pipeline and tests live inside that folder.
