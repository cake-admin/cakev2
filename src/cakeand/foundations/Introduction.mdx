# cake&

**cake&** is Lenovo’s design system: the colors, type, spacing, and UI
components that Lenovo products are supposed to share. This site is the
**Storybook** for cake& — a catalog you can click through in the browser,
with live examples for every component.

You do not have to be a developer to use cake&. If you want to *look something
up*, stay on this Storybook. If you want to *build a clickable prototype* with
the real components, use the **Devkit** (a small starter project you download).

## Storybook vs the Devkit

These are two different tools. Pick the one that matches what you are doing

## The Devkit

The Devkit is the fastest way to start building with cake&. It is a small
starter project (not a copy of this whole repository). You put it on your
computer, run a few commands, and get a local preview in the browser. From
there you can open the folder in Cursor and ask for the screens you need.

You never log in to GitHub to download it. Each version ships as a public
**release file** (a `.tgz`). The current kit is **v4.2.3**:

<p>
  <a href="https://github.com/cake-admin/cakev2/releases#release-v4.2.3">
    <strong>Newest cake&amp; release — v4.2.3</strong>
  </a>
</p>

On that page, look for the file named `cake-admin-cakeand-4.2.3.tgz`. That is
the kit. The Devkit starter already points at one of those files for you, so
most people never copy the URL by hand.

### Why use it

- You get **real cake& components**, not pictures of them. Buttons, tables,
  date fields, and the rest behave the way they do in this Storybook.
- **Light and dark** (and Windows high contrast) already work.
- The **Rookery New** font and design tokens are wired in. You do not set
  those up yourself.
- A coding agent can build from the **actual component names and props**,
  instead of inventing a look-alike.
- Sharing the prototype is sharing a folder that runs — useful in critiques
  and handoff.

### What you get, and how to use it

Once the starter is on your machine, the folder already contains:

- **CakeProvider** — one wrapper that turns on cake& color, type, and theme.
  You should not need to add a second one.
- **Components** — import from `@cake-admin/cakeand` (one path). Browse this
  Storybook when you want to see a control’s options before you ask the agent
  to use it.
- **Tokens** — the same variables as Figma, as CSS custom properties.
- **`context/`** — notes for Cursor / Claude Code: a list of components, then
  a short file per component. **Do not edit `context/` by hand**; a cake&
  release regenerates it.
- **`npm run cake:update`** — pulls a newer cake& version into that same
  folder when you are ready.

Typical loop: keep Storybook open in a tab for reference, keep the Devkit
preview open in another, and describe the screen you want in the agent. For
example: *“Build a settings page with tabs and a save button, using cake&
components.”*

The numbered install steps are next. Extra detail for “add cake& to an app we
already have” lives on
[Getting Started](?path=/docs/cake-maintenance-getting-started--docs).

## Step-by-step: download the Devkit

You need [Node.js](https://nodejs.org/) installed (the **LTS** version is
fine). That gives you the `npm` command. Then open a terminal — **Terminal** on
Mac, **PowerShell** on Windows.

### Path A — I want a new prototype (recommended)

This copies only the starter onto your machine. It is **not** a clone of the
whole design-system repo. No GitHub password or token.

**1.** Download the starter into a folder named `my-prototype` (any name is
fine):

```bash
npx degit cake-admin/cakev2/starter my-prototype
```

The first time, your computer may ask “ok to proceed?” — type `y` and press
Enter. `npx` means “run this helper once”; `degit` means “copy these files,
without git history.”

If that command fails, this does the same thing:

```bash
npx giget@latest gh:cake-admin/cakev2/starter my-prototype
```

**2.** Move into that folder:

```bash
cd my-prototype
```

**3.** Install the pieces the project needs (this can take a minute):

```bash
npm install
```

**4.** Start the local preview:

```bash
npm run dev
```

Your terminal will print a link, usually `http://localhost:5173`. Open it in a
browser. You should see a small cake& page with a light/dark toggle.

**5.** Open the `my-prototype` folder in Cursor (or another coding agent) and
ask for what you want.

To pull a newer cake& version later, from that same folder run
`npm run cake:update`.

### Path B — I already have an app

If an engineer already has a React project, cake& installs from a release
file. Still no login:

1. Open the [v4.2.3 release](https://github.com/cake-admin/cakev2/releases#release-v4.2.3)
   and copy the `cake-admin-cakeand-4.2.3.tgz` download link (or use the
   command below).
2. In the project folder, install that file, then the five libraries cake&
   expects to share with the app:

```bash
npm install https://github.com/cake-admin/cakev2/releases/download/v4.2.3/cake-admin-cakeand-4.2.3.tgz
npm install react react-dom styled-components radix-ui lucide-react
```

3. Wrap the app **once** in `CakeProvider` (the starter already does this):

```tsx
import { CakeProvider, Card, HeroCard, Button } from '@cake-admin/cakeand';

<CakeProvider mode="light.a">
  <Card>
    <HeroCard title="Hello" actions={<Button size="lg">Get started</Button>} />
  </Card>
</CakeProvider>;
```

The extra wiring (theme on the page, fonts, a shared copy of
`styled-components`) is already done in the starter. If you are adding cake&
to an existing app, follow the numbered checklist on
[Getting Started](?path=/docs/cake-maintenance-getting-started--docs).

## What’s in this Storybook

- **Foundations** — color, type, space, elevation.
- **Components** / **Elements** — click a component, change the controls,
  copy the usage snippet. Start with Button if you want a simple example.
- **Cake& Maintenance** — for the design-system team (how we build and ship).
  Designers building prototypes can skip it.

## Running this Storybook on your machine (cake& team)

If you cloned the full `cakev2` repo to work on the system itself:

```bash
npm run storybook              # http://localhost:6006
npm run build-storybook        # static build
```

The folder path contains `&`, which breaks some Windows shortcuts. Use
`npm run storybook` rather than `npx storybook`.
