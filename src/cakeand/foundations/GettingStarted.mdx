# Getting Started

This is the longer walkthrough. If you only need the four commands to start a
prototype, use [Introduction](?path=/docs/introduction--docs) instead.

You do **not** need a GitHub password, a `.npmrc` file, or access to GitHub
Packages. The starter downloads from a public release file.

## Start a new prototype

You need [Node.js](https://nodejs.org/) (LTS). Then, in a terminal:

**1.** Copy the starter into a new folder (change `my-prototype` if you like):

```bash
npx degit cake-admin/cakev2/starter my-prototype
```

`npx` runs a helper once. `degit` copies files **without** git history, so you
get a clean project — not a fork of the whole design system.

If `degit` fails (it is older software), either of these is equivalent:

```bash
npx giget@latest gh:cake-admin/cakev2/starter my-prototype
```

```bash
git clone --depth 1 https://github.com/cake-admin/cakev2
cp -r cakev2/starter my-prototype
```

On Windows, copy the `starter` folder out of the clone in File Explorer if you
prefer not to use `cp`.

**2.** Go into the folder, install, and start the preview:

```bash
cd my-prototype
npm install
npm run dev
```

Open the `http://localhost:5173` link your terminal prints.

## What is already wired up

You should not have to configure these yourself:

- **CakeProvider** — one wrapper that turns on cake& colors, type, and the
  light/dark toggle
- **Design tokens** — the same variables as Figma, as CSS custom properties
- **Rookery New** — the cake& font, loaded for you
- **Components** — import from `@cake-admin/cakeand` (one path)
- **Agent notes** — a `context/` folder so Cursor or Claude Code uses real
  component names instead of guessing

## Working with a coding agent

Open `my-prototype` in Cursor and describe the screen you want. The starter
includes `AGENTS.md` and `context/`:

| File | What it is |
| --- | --- |
| `context/cake-components.md` | A one-line list of every component. The agent should read this first. |
| `context/components/<name>.md` | Props and a real example for one component. |
| `context/cake-tokens.md` | Every color/space/type token. |

These files are generated from this Storybook. **Do not edit `context/` by
hand** — a cake& release regenerates it.

## Adding cake& to an app you already have

Use this only if a developer already has a React app. Prefer Path A on
[Introduction](?path=/docs/introduction--docs) when you can.

**1.** Open the [latest GitHub release](https://github.com/cake-admin/cakev2/releases/latest)
and copy the `cake-admin-cakeand-….tgz` URL.

**2.** Install cake& and the libraries it shares with the app:

```bash
npm install https://github.com/cake-admin/cakev2/releases/download/vX.Y.Z/cake-admin-cakeand-X.Y.Z.tgz
npm install react react-dom styled-components radix-ui lucide-react
```

Those five extra packages are **peer dependencies**: they are not bundled
inside cake&, so the app has exactly one copy of React and
`styled-components`. Two copies of `styled-components` means components look
unstyled, with no clear error. In Vite, keep this in `vite.config.ts` (the
starter already has it):

```ts
export default defineConfig({
  resolve: { dedupe: ['styled-components', 'react', 'react-dom'] },
});
```

**3.** Wrap the app **once**:

```tsx
import { CakeProvider, Card, HeroCard, Button } from '@cake-admin/cakeand';

<CakeProvider mode="light.a">
  <Card>
    <HeroCard title="Hello" actions={<Button size="lg">Get started</Button>} />
  </Card>
</CakeProvider>;
```

Copy three things from the starter if they are not already there:

1. `resolve.dedupe` in `vite.config.ts` (above)
2. `import '@cake-admin/cakeand/cakeand.css'` at the **top** of your main
   entry file (`src/main.tsx` in the starter)
3. `data-theme="light.a"` on the `<html>` tag in `index.html`

`CakeProvider` writes `data-theme` onto `<html>` so menus and dialogs that
pop over the page (Modal, Dropdown, Tooltips) stay on the same theme. If you
only wrap a `<div>`, those popovers can jump back to light.

Modes: `light.a` (default), `dark.a`, `win hct`. The first paint uses whatever
is on `<html>` in `index.html`, so keep that in sync with `mode`.

## Updating cake&

From a starter project:

```bash
npm run cake:update
```

From an app you added cake& to yourself, install the newer `.tgz` URL again.
There is no `cake:update` script outside the starter.

Each project pins **one exact version** on purpose. A link that always meant
“latest” would look convenient, then break installs when the file on that
URL changed.

## Troubleshooting

| What you see | What to try |
| --- | --- |
| No color; tokens look empty | The cake& CSS file did not load. Check the `cakeand.css` import in `src/main.tsx`. |
| Your CSS cannot override cake& | Import your stylesheet **after** the cake& one. |
| Components ignore the theme | Two copies of `styled-components`. Run `npm ls styled-components`. |
| Wrong theme for a split second on load | `data-theme` in `index.html` does not match `CakeProvider` `mode`. |
| Menus/dialogs are the wrong theme | Do not pass `scope="subtree"` if you use Modal, Dropdown, or Tooltips. |
| `npm error EINTEGRITY` | Delete `package-lock.json` and reinstall (starter: `npm run cake:update`). |
| npm fails oddly on Windows | A folder name containing `&` breaks npm. Rename the folder. |

Use **npm**. Other package managers can install from a URL, but this starter
is tested with npm only.
