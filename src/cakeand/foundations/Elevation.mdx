# Elevation

Elevation separates a surface from the one behind it. Figma defines six levels,
`elevation/0` – `elevation/5`, each a two-layer drop shadow: a tight **key**
layer that grounds the surface over a wider **ambient** layer that softens the
edge. Both layers draw in `--color-elevation-drop-shadow-light` and
`-heavy`, so shadows re-theme instead of being a fixed black.

Pick a level by what the surface *is*, not by how strong the shadow looks. Use
the **Theme** toolbar to check any level in Light A, Dark A, and Win HCT.

The ambient blur is always exactly twice the key blur. Keep that ratio if you
ever hand-author a shadow.

## Usage

```css
box-shadow: var(--elevation-2);
```

Prefer the CSS variable — it re-resolves on `data-theme` with no re-render. The
same values are on the theme object for JS consumers under `CakeThemeProvider`:

```ts
box-shadow: ${(p) => p.theme.elevation[2]};
```

Elevation is decorative: in Win HCT both layers collapse to opaque `#202020`,
and it conveys nothing to a screen reader.

## Legacy tokens

Every cake& component now uses a numbered token. Two older tokens survive in
`cake-vars.css` for apps that already reference them, but nothing in the system
does — and nothing new should. They are not levels; each is a single-layer
approximation of one.

## Open questions

- **Rich Tooltip sits at level 5**, the same depth as Modal. Its inline shadow
  matches exactly, so the token changes nothing — but level 2 (where Simple
  Tooltip sits) or 3 would be the conventional choice.
- **Nothing uses level 1 or 4.** Gaps in the component set, not dead tokens —
  level 4 waits on a drawer or sheet.
